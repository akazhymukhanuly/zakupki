# Развёртывание на сервере

## Что нужно от сервера

| | Минимум | Рекомендуется |
|---|---|---|
| ОС | Linux (Ubuntu 22.04 / 24.04, Debian 12) | то же |
| CPU / RAM | 2 vCPU / 4 ГБ | 4 vCPU / 8 ГБ |
| Диск | 40 ГБ SSD | 80 ГБ SSD + отдельный диск/хранилище под бэкапы |
| ПО | Docker + Docker Compose plugin | то же |
| Сеть | домен (A-запись на сервер), открыты порты 80 и 443 | + доступ к SMTP и к папке обмена с 1С |

Этого хватает с запасом на сотни пользователей и сотни тысяч позиций. Проверено нагрузочно: 3 000 СЗ / 15 000 позиций — реестр и пул открываются за 0,1–0,15 с.

## Состав (docker-compose.yml)

| Сервис | Что делает | При сбое |
|---|---|---|
| `db` | PostgreSQL 16, данные в томе `pgdata` | перезапускается автоматически |
| `web` | приложение (gunicorn, 3 процесса), при старте применяет миграции | healthcheck `/health/` каждые 30 с, перезапуск |
| `scheduler` | автозакрытие, SLA-напоминания, очистка сессий, обмен с 1С каждые 10 мин | ошибка одной задачи не останавливает остальные |
| `backup` | `pg_dump` раз в сутки, хранит 14 дней | пишет `BACKUP FAILED` в лог |
| `caddy` | HTTPS (сертификат Let's Encrypt получает и продлевает сам) | перезапуск |

Все сервисы с `restart: unless-stopped` — поднимаются после перезагрузки сервера.

## Первый запуск

```bash
git clone https://github.com/akazhymukhanuly/zakupki.git && cd zakupki
cp .env.example .env
nano .env            # домен, пароли, SMTP, папки — см. комментарии в файле
docker compose up -d --build
docker compose exec web python manage.py createsuperuser
```

Дальше войти под созданным администратором → «Загрузка справочников» → скачать шаблон, заполнить (или взять заполненный от заказчика) → «Проверить» → «Загрузить». Временные пароли новых пользователей показываются один раз.

То же из командной строки:

```bash
docker compose cp справочники.xlsx web:/tmp/refs.xlsx
docker compose exec web python manage.py import_refs /tmp/refs.xlsx --dry-run
docker compose exec web python manage.py import_refs /tmp/refs.xlsx
```

> Демо-данные (`seed_demo`) на боевом сервере не запускаются: команда откажется, если `DEMO_MODE=0`.

## Обновление версии

```bash
cd zakupki && git pull
docker compose up -d --build
```

Миграции применяются автоматически при старте `web`. Перед крупным обновлением сделайте ручной бэкап (ниже).

## Бэкапы и восстановление

Автоматически: ежедневно в `BACKUP_HOST_DIR` (по умолчанию `./backups`), хранятся `BACKUP_KEEP_DAYS` дней. **Копируйте эту папку на другой сервер/хранилище** — бэкап на том же диске не спасёт от отказа диска.

Ручной бэкап:

```bash
docker compose exec db pg_dump -U zakupki zakupki | gzip > backup_$(date +%F).sql.gz
```

Восстановление:

```bash
docker compose stop web scheduler
gunzip -c backups/zakupki_ГГГГММДД_ЧЧММ.sql.gz | docker compose exec -T db psql -U zakupki -d zakupki
docker compose start web scheduler
```

Проверяйте восстановление на тестовой машине хотя бы раз в квартал.

## Мониторинг

* `https://домен/health/` → `{"status": "ok"}` (200) или 503 при недоступности БД — подключите к любому внешнему мониторингу (UptimeRobot, Zabbix и т. п.).
* Ошибки 500 приходят письмом на `DJANGO_ADMINS` (нужен настроенный SMTP).
* Логи: `docker compose logs -f web scheduler`.

## Обмен с 1С через папку

Задайте в `.env` `ONEC_EXCHANGE_HOST_DIR` — папку на сервере, доступную и 1С (сетевая шара / SFTP / общий том). Внутри создаются:

* `out/` — система кладёт подписанные договоры `contracts_*.xml` (1С забирает);
* `in/` — 1С кладёт `receipts_*.xml|csv|xlsx|json` (поступления) и `payments_*.*` (оплаты);
* `archive/` — обработанные файлы, `error/` — файлы с ошибками + `.log` с описанием.

Повторная загрузка того же документа (договор + номер + дата) не задваивает поступления и оплаты. Ручной обмен через раздел «Обмен с 1С» работает всегда, в том числе если папка не настроена.

## Безопасность — что уже сделано

* `DEBUG` выключен по умолчанию, `SECRET_KEY` обязателен, секреты только в `.env` (не в Git).
* HTTPS, secure-cookies, HSTS; проверка CSRF во всех формах (покрыто тестом).
* Блокировка входа после 5 неверных паролей на 15 минут (настраивается).
* Пароли: минимум 8 символов, не из списка простых.
* Документы (СЗ, закупки, договоры, поступления, оплаты) в админке только для просмотра — менять их можно лишь через интерфейс с проверкой правил.
* Каждый запрос выполняется в транзакции; номера документов выдаются через счётчик с блокировкой (без дублей при одновременной работе).
* Сессия — 12 часов.

## Локальный запуск (разработка / демо)

```bash
./start.sh
```

Создаёт `.env` с `DJANGO_DEBUG=1` и `DEMO_MODE=1`, SQLite и демо-данные. Тесты: `.venv/bin/python manage.py test core`.
