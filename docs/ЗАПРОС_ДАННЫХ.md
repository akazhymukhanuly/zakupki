# Что нужно от заказчика для запуска системы «Закупки»

Ниже — всё, что нужно для перехода с демо на рабочую систему. Приоритет: **А** — без этого не запустимся, **Б** — нужно в первый месяц, **В** — можно позже.

## 1. Справочники — один Excel-файл по шаблону (А)

Шаблон: `docs/Шаблон_справочников.xlsx` (также скачивается в системе: «Загрузка справочников» → «Скачать шаблон»). На листе «Инструкция» — правила и примеры. Файл можно присылать частями и повторно: записи обновляются, ничего не удаляется.

| Лист | Что заполнить | Откуда взять | Обязательные колонки |
|---|---|---|---|
| Станции | станции / филиалы (ГРЭС-1, ГРЭС-2 …) | оргструктура | Наименование |
| Подразделения | все подразделения, которые будут подавать СЗ, и их руководителей (они согласуют СЗ) | оргструктура / кадры | Наименование |
| Пользователи | все, кто будет работать в системе, с ролями | кадры / IT | Логин, Фамилия, Имя, Роли |
| Статьи бюджета | статьи, на которые относятся закупки | бюджет / 1С | Код, Наименование |
| Категории | группы закупок (канцтовары, IT, хозтовары…) — по ним подбираются поставщики | отдел закупок | Наименование |
| Номенклатура | что закупается регулярно, с кодами 1С | **выгрузка из 1С** (справочник «Номенклатура») | Наименование, Ед. изм. |
| Поставщики | действующие поставщики, e-mail для запросов КП, какие категории закрывают | **выгрузка из 1С** (справочник «Контрагенты») + отдел закупок | Наименование |
| Рамочные договоры | действующие рамочные договоры — к ним система будет предлагать спецификации | договорной отдел | Номер, Дата, Поставщик |
| Коридоры согласования | границы сумм, кто согласует, срок в рабочих днях (по умолчанию — как в макете: 5 / 50 млн ₸) | руководство | Код, Название, Согласующие роли, Срок |

Требования к данным:

* **Коды 1С** у номенклатуры и поставщиков — желательно сразу: по ним поступления из 1С сопоставляются автоматически, без ручной разноски.
* **БИН** поставщиков — 12 цифр, по нему система находит поставщика при повторной загрузке.
* **E-mail** пользователей — для уведомлений; e-mail поставщиков — для запросов КП.
* Роли: Инициатор, Руководитель подразделения, Закупки (ОМТС), Главный инженер, Финансы (ФЭО), Юристы (ЮО), Генеральный директор, ПТО, Бухгалтерия, Администратор. У человека может быть несколько ролей.
* Статьи бюджета — с годовым лимитом, чтобы в карточке показывался остаток.

## 2. Решения по правилам работы (А)

1. **Права доступа** — подтвердить или поправить матрицу ролей (в системе: «Роли и права»; в ТЗ раздел 10 пустой).
2. **Кто согласует СЗ** — руководитель подразделения (как сейчас) или другая схема (например, двухуровневая: руководитель → финансист)?
3. **Коридоры согласования** — сейчас как в макете: 🟢 до 5 млн ₸ — главный инженер (1 р.д.); 🟡 5–50 млн — + финансы и закупки параллельно (2 р.д.); 🔴 свыше 50 млн — + юристы и гендиректор (5 р.д.); по действующему договору — ПТО + финансы. Подтвердить суммы, составы и сроки; праздники для расчёта рабочих дней.
4. **Сроки:** через сколько дней автоматически закрывать поставленную позицию (сейчас 14); через сколько дней напоминать о срочной позиции без движения (сейчас 2).
5. **Портал поставщика** — достаточно ссылки без регистрации (как сейчас) или нужен личный кабинет?
6. **Распределение оплат по позициям** — подтвердить, что это справочная информация, не бухгалтерская (п. 8 ТЗ, нужно зафиксировать в договоре).

## 3. Интеграция с 1С (А — вопросы, Б — настройка)

1. Конфигурация и версия 1С (Бухгалтерия / УТ / ERP / КА; релиз), где работает (свой сервер, облако).
2. Контакт 1С-программиста.
3. Способ обмена: **общая папка** (готово в системе, самый простой вариант) или HTTP-сервис 1С.
4. Какие документы 1С считаются поступлением (поступление товаров и услуг, акт) и оплатой (платёжное поручение исходящее, списание с р/с).
5. Нужно ли сворачивать одинаковые позиции из разных СЗ в одну строку при выгрузке договора (п. 6.1 ТЗ).
6. Пример выгрузки из 1С: 2–3 реальных документа поступления и оплаты (можно обезличить) — чтобы проверить сопоставление на живых данных.

Форматы файлов обмена — в README, раздел «Интеграция с 1С». Для 1С-программиста: поле `IDПозиции` (вида `СЗ-12/3`) из выгруженного договора нужно сохранить в строке документа и вернуть в выгрузке поступления.

## 4. Инфраструктура (А)

| Что | Зачем |
|---|---|
| Сервер Linux: 2–4 vCPU, 4–8 ГБ RAM, 40–80 ГБ SSD (свой или облако, напр. PS Cloud / Hoster.kz / Yandex Cloud) | размещение системы |
| Доменное имя (напр. `zakupki.company.kz`) и доступ к DNS | адрес и HTTPS-сертификат |
| SSH-доступ для установки и обновлений | развёртывание |
| Почтовый ящик для отправки (SMTP: сервер, порт, логин, пароль), напр. `zakupki@company.kz` | уведомления на e-mail |
| Место для бэкапов вне сервера (другой сервер / S3 / NAS) | защита от отказа диска |
| Сетевая папка, доступная и серверу, и 1С | автоматический обмен с 1С |
| Ответственный администратор со стороны заказчика | доступы, пользователи, бэкапы |
| Используется ли Active Directory / вход через корпоративную учётку | можно сделать вход по доменной учётке (этап 2) |

## 5. Бланки документов (Б)

* Образец служебной записки (Word/PDF), если есть корпоративный бланк — подгоним печатную форму.
* Образец запроса КП поставщику.
* Образец договора / спецификации — если нужно формировать документ договора из системы (сейчас договор оформляется вне системы, в системе — карточка и спецификация).

## 6. Исторические данные (В, по желанию)

По умолчанию стартуем «с чистого листа»: в системе новые СЗ, а текущие закупки доводятся по-старому. Если нужно:

* **Открытые СЗ/закупки** на момент запуска — перенесём по отдельному шаблону.
* **Цены прошлого года** по номенклатуре (номенклатура, цена, дата, поставщик) — для отчёта «Экономия против прошлогодней цены» с первого дня.

## 7. Контакты и сроки

* Ответственный со стороны заказчика (ФИО, телефон).
* 2–3 ключевых пользователя для пилота: инициатор, закупщик, бухгалтер.
* Желаемая дата пилота и дата полного запуска.
